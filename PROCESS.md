# Campus Ride Share Development Process

## Chosen Process Model: Scrum

Campus Ride Share uses Scrum to develop a web application for Southeast Missouri State University students. The application will help students find carpool opportunities by allowing them to create ride-offer and ride-request posts, browse posts, and filter posts by trip details.

Scrum fits this project because the two-person team has a clear core product but expects details to change during development and usability review. Scrum lets the team prioritize the most valuable work, create a small working increment, and adjust later work based on feedback. To keep the first version manageable, the project does not include payments, GPS tracking, real-time messaging, or automatic ride matching.

## Board Workflow

The team uses a GitHub Projects board with three columns:

- Backlog
- In Progress
- Done

The product backlog contains user-focused features and technical tasks. A card moves to In Progress when work begins. It moves to Done only after it works correctly, both team members review it, it is committed to GitHub, and the team has basic test evidence or documented manual testing.

## Sprint 1: Core Ride Posting

- **Sprint length:** Two weeks
- **Sprint goal:** Build the basic workflow that lets students create a ride offer or ride request and browse available ride posts.
- **Sprint backlog:** Browse ride offers and ride requests; create a ride-offer post; create a ride-request post; display ride offer/request type; validate required post fields.
- **Later backlog items:** Destination and date filtering, contact-information display, editing/deleting posts, ride-time display, and other improvements.
